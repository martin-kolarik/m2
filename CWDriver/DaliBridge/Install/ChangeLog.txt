Version 1.0.668/R beta 18.12.2008
- BUG: events received from DALI caused sending of next packet event if
       the previous packet was still unacked. That premature send caused
       with high probablity frame collision on DALI.
- CHG: Group and all addresses allowed for "scene" command.

Version 1.0.648/R beta 14.11.2008
- BUG: "param" command did not use all parameters, it set the first found
        value to all parameters
- NEW: Commands "group_add <adr> <grp>", "group_remove <adr> <grp>",
       "scene_add <adr> <scene> <level>", "scene_remove <adr> <scene>",
       "scene <adr> <scene>" added.

Version 1.0.622 beta 21.10.2008
- BUG: "send_delay" parameter value was obtained from "output_queue_length" key.
- NEW: Driver now accepts command "program_file <Device>.<Linie> <FilePath>",
       when sequence of sent and expected data is read from the file and sent
       to DALI. After exhausting file lines event "program" is fired.

Version 1.0.611 beta 14.10.2008
- NEW: PAR file now can contain [device] "send_delay" parameter, which sets delay
       between packets sent to interface. Default value is 0 (ms), maximal effective
       value is 2000 (ms).

Version 1.0.607 beta 13.10.2008
- BUG: Unexpected interface response caused infinite receive loop without reporting
       content of bad packet.
- BUG: Limitation to 10 successive frame link errors was weak, counting was
       reset after any meaningful interface response, including ACK.
- BUG: Polling probes could be sent after driver/device stop. This could cause
       application crash.        

Version 1.0.589 beta 10.10.2008
- BUG: Response addresses were badly decoded, it caused that data from
       second and fourth linies were unrecognized.
- BUG: Only first linie was reset during driver start.
- CHG: In case of frame link error occurrence driver repeated communication
       indefnitely. Now it drops current packet after 10 successive frame
       link errors.
- NEW: New command "reset_interface <linie>" was addedd to allow programmatic
       reset of interface.

Version 1.0.1782 beta 21.9.2008
- INF: The majority of changes was done to adhere (non-standard) behavior of
       Helvar buttons.
- BUG: Event commands (dali events, reset notifications) could stop timeout

       was stopped.
- NEW: Polling is enabled for all four linies using new "set_poll_period"
       command.
- NEW: Commands "get_addresses" and "load_addreses" added, sequence of
       address contains both short and long addresses. 
- NEW: Driver is able to connect more devices -- endpoints are created using
       "create" command a removed by "delete" command.

- NEW: Addressing now works for all linies.
- CHG: All addresses are extended by device name, e.g. "Device.2.all" for all
       devices in line 2. 
- CHG: Check of programmed addresses changed from DALI Check Address command to
       DALI Read Address command.
- CHG: Polling and connection definitions were moved from parametric file to
       driver query procedures.
- CHG: Addressing added devices does not scan linie before addresing and it
       requires valid addresses to be set.
- CHG: More descriptive labels of log records.

Version 1.0.1779 beta 13.9.2008
- BUG: Polling of device stopped if during waiting for response some addressing
       command was requested.
- NEW: Driver now reports change of status if status was previously known and
       now it is unavailable (device does not respond).
- NEW: New command "program_scan" was added, the command scans selected linie
       and fills internal address structures. The command is always run before
       programming, when "program_added" is requested.
- NEW: Addressing commands (including "program_scan") fire event about found devices.
       The event starts with "found ...".
- NEW: Command "reset_address <adr>" was added, using <adr> all or specific device
       address can be reset.
- CHG: Command "program_missing_addresses" was renamed to "program_added", command
       "program_addresses" was renamed to "program_all", and command "readdress"
       was renamed to "program_readdress".
- CHG: Commands "get_addresses" and "load_addresses" were removed.
- INF: "program_readdress" still requires internal address structures filled
       (using "program_scan" or "program_all" command).
- INF: "program_added" command starts internally before self run "program_scan"
       command to be sure the addresses will be correct.

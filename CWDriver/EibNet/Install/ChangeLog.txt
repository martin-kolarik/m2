Version 1.0.605 beta

Version 1.0.1710 beta

       synchronized. This caused step-by-step stopping of synchronous CW
       communication. The effect was hidden sometimes, because the driver forces
       CW to accept asychronous values as well.    

Version 1.0.1693 beta
- CHG: Sequence correction algorithm from #1672 was modified to accept
       not only skipping of sequence number, but also an insertion of sequence number.
- CHG: Tunneling connection now discards packets coming with unexpected ChannelId.
- BUG: Connection did not corectly resolved socket state, when no data were
       returned after notification that data are prepared. This ocassionaly
       resulted to mismatched receiving (not really received packet, possible
       from different source, was processed).
- BUG: Configuration errors (debug, id, mode, ...) were badly reported.

Version 1.0.1672 beta
- CHG: Some packets from tunneling device come with unexpectedly high SequenceNumber.
       But next packet received has correct sequence, unfortunately now lower than the
       unexpected one. This forces driver to wait until received packets step by step
       increase to the bad SequenceNumber, so all packets during this period are discarded.
       The workaround remembers previous SequenceNumber and if the next packet after
       unexpected one uses correct number, driver detects this and it does not
       discard no packets.

Version DEBUG 1.1.602 12.10.2008
- BUG: DriverQueryProc SetRxIndex a SetTxIndex ignored input parameter
       and always set indexes to 0.
- CHG: DriverQueryProc PutCharSeq and GetCharSeq now check if parameter
       has numeric type and, in this case, they put or get character ord
       instead of character itself (or encode string).

Version DEBUG 1.1.586 7.10.2008
- BUG: Characters above 127 were converted from UNICODE to ANSI (for CW), so
       bytes received were damaged. Confusion is caused by logical switch from
       bytes (serial channel) to characters (CW, necessary). 

Version DEBUG 1.1.583 6.10.2008
- BUG: DriverQueryProc GetCharSeq did not fill output parameter (string) if data
       were read behind queue end. Output parameter in this case contained previous
       value (previously read string, this is behaviour of CW5/CW6).
- CHG: Versions are counted not by SVN but by HG.

Version DEBUG 1.1.1792 28.9.2008
- BUG: # characters were not escaped when data from ASCDRV
       compatible DriverQueryProc procedures have been returned. This
       could lead to confusion in # character interpretation.
- BUG: ASCDRV compatible DriverQueryProc procedures set result of
       operation to output parameter even if the parameter was used
       for operation result. This could lead to confusion of output
       parameter meaning.
